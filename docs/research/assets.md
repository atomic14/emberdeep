## 3. Recommendation: cohesive dark-fantasy dungeon look

**Go all-KayKit for everything the camera sees.** Specifically:

1. **Environment: KayKit Dungeon Remastered 1.0** (203 GLBs). Single 1024 atlas means one material for the whole level, which is ideal for three.js (merge geometry per room, or `InstancedMesh` per piece type; one draw call per piece type). The 4-unit grid is clean: a 4x4 floor tile = one party-member footprint = one tactical grid cell works perfectly for a BG1-style camera. Walls are 4 tall, which reads well at a 30-45 degree orthographic tilt without hiding the floor behind them (you will still want a wall-fade shader or to omit the two camera-facing walls per room, as every isometric game does).
2. **Party: KayKit Adventurers 1.0** (Knight, Mage, Rogue, Rogue_Hooded, Barbarian). Ranger = Rogue_Hooded + crossbow until you grab 1.1 from itch.io.
3. **Enemies: KayKit Skeletons 1.0** (Warrior, Mage, Rogue, Minion) and, for variety, Kenney Graveyard characters are *not* recommended (style clash, see below). The Skeleton pack's `Skeletons_Awaken_Floor`, `Spawn_Ground_Skeletons`, `Death_C_Skeletons_Resurrect` and `Taunt` clips are exactly what a dungeon crawler wants for ambushes.
4. **Set dressing for undead/crypt areas: KayKit Halloween Bits** (crypt, coffins, bones, skulls, shrines, dead trees, lanterns). It is the same 1024-atlas, same proportions, same colour grading as Dungeon Remastered, so it mixes freely.
5. **Prototype Bits** for greyboxing new room shapes before art is chosen.

Why not mix in Kenney or Quaternius for visible geometry:

- **Kenney** kits are chunkier, more saturated, use a 512 palette-style colormap, and the characters are blocky-chibi with rigid-body (non-skinned) animation. Side by side with KayKit's smoother, slightly stylised proportions the clash is obvious. Kenney's Mini Dungeon also uses a 1-unit tile vs KayKit's 4-unit tile, so nothing lines up without rescaling. Keep Kenney for **audio only** (RPG Audio, Impact, Interface, UI are excellent and license-free) and, at most, the Fantasy Town Kit if you later want a cheap above-ground hub and are willing to accept the visual break between hub and dungeon.
- **Quaternius** is closer in spirit to KayKit (both low-poly flat-shaded), but the only dungeon we could fetch is the 2018/2019 FBX-only pack with a different, noisier palette texture, and we could not get any Quaternius characters. Not worth the conversion effort when KayKit covers the same ground in GLB already.

Cohesion checklist for the three.js side:

- Use `MeshStandardMaterial` or `MeshToonMaterial` with the KayKit atlas and `flatShading` off; KayKit's bake expects smooth normals. A subtle fog + warm point lights at `torch_lit` positions gets the "dark fantasy" read quickly with zero extra art.
- Characters and props share the exporter convention (Blender, Y-up, meters), so no per-pack scale fixes are needed within KayKit.
- The KayKit rig is shared between Adventurers and Skeletons, so any clip from one pack can be played on the other via `AnimationUtils`/`SkeletonUtils.clone` with no retargeting (bone names match; verify once in code since the 2024 Skeleton export has slightly more bones).
- Weapons are separate `.gltf+.bin`; attach them to the hand bone nodes in the rig (KayKit docs name them `handslot.l` / `handslot.r`; inspect the node list in `Knight.glb` to confirm).

**Audio stack:** Kenney (4 packs, CC0) for footsteps, impacts, doors, UI; OGA RPG Sound Pack (CC0) for swings, unsheathe and monster vocals; Little Robot Fantasy Library (CC-BY) for spells and chest/gold if you are fine with one attribution line; OGA CC0 drones as the exploration bed; Kevin MacLeod (CC-BY) for the four music slots. Everything is in `.ogg` or `.mp3` already, which Web Audio decodes natively.
